# AGENTS.md — правила проекта

> Источник правды для любого ИИ-агента в этом проекте. Сначала прочитай этот файл и `MEMORY.md`.

## Проект
- Что делает: <одна фраза>. Для кого: <кто>.
- Режим: <1 прототип / 2 MVP / 3 всерьёз>. Стек: <...>.
- Запуск: `start.bat` (Windows) / `start.command` (Mac/Linux). Основная ветка: `main`.

## Цикл работы (на всю жизнь проекта)
1. **Сохранение:** перед шагом коммит `wip: <что делаю>`.
2. **Короткая перебежка:** один шаг, который можно увидеть или потрогать.
3. **Честный отчёт:** сборка не падает, консоль чистая. Пиши только правду: «собрал», «прогнал сценарий», «проверить не смог».
4. **Стоп-кран:** дай человеку проверить руками, всегда с ожидаемым результатом:
   «Готово: [кусок]. Что проверил я: [...]. Твоя очередь: [действие], должно [результат]. Если иначе — скинь скриншот или текст ошибки. Всё ок — напиши "ок".»
   В режиме 1 — после готового экрана/функции, не после каждой мелочи.
5. **После «ок»:** тег `ok-N` (следующий номер), дамп данных (режимы 2–3), в `MEMORY.md` → «Где остановились» 3 строки.
6. **Замечание человека:** сначала правило в `MEMORY.md` → «Грабли», потом код.
7. **«А ещё давай…»:** запиши в `MEMORY.md` → «Потом», скажи одной фразой, продолжай шаг.

## ПАНИКА / ОТКАТ / «верни как было» (любой регистр, также `panic`)
1. Немедленно останови правки. **Ничего не удаляй.**
2. Выполни ровно это:
```
git switch -c rescue-<время>
git add -A && git commit -m "rescue: состояние до отката"
git switch <основная-ветка>
git reset --hard <последний-тег-ok-N>
```
3. Запусти проект.
4. Доложи одной фразой: куда откатил, что лежит в `rescue-*`, затронута ли база. Откат кода базу **не** откатывает: если схема менялась, предложи восстановить из `backups/`.

## Правило двух попыток
Баг не чинится со 2-й попытки → стоп, без костылей. Откат к последнему `ok-N` (как в ПАНИКЕ), причина в `MEMORY.md`, объяснение человеку простыми словами.

## Данные не живут в git
- В `.gitignore`: `.env`, `*.db`, `*.sqlite*`, `data/`, `backups/`, `*.session`.
- В git только миграции (структура базы) и тестовые данные без личной информации.
- Дамп в `backups/`: при каждом `ok`, перед миграцией, при запуске. Хранить последние 7.
- Раз в неделю напоминай скопировать `backups/` за пределы папки проекта.

## Ключи
- Никогда в код, коммиты, `MEMORY.md`. Только `.env` (+ `.env.example` без значений).
- Денежные ключи (платежи, боевая БД) — через скрипт ввода в терминале, не через чат.
